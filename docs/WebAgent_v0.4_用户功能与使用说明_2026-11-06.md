# WebAgent v0.4 用户功能与使用说明

更新日期：2026-11-06。本说明根据当前界面、源码、四阶段验收记录及用户随后反馈的报错编写。本文解释现状，不代表已经修复报错，也不增加新功能。

## 1. 现在到底做到了什么

WebAgent 希望帮你完成这样的事：你说清楚要检查网站的哪个功能，系统设计测试、操作浏览器、读取结果，再判断是否符合要求，并保留记录。

四轮开发后，这条处理链已经接起来：需求设计、需求审核、根据当前页面生成操作、持续操作同一个浏览器、核对证据，以及有限的补证和故障恢复。Streamlit 界面和命令行也接上了这条链。

但“处理链已接通”和“普通用户输入任意需求都能稳定完成”是两回事。**现在还不能把它当成成熟的通用网站测试产品。** 本地验收使用了真实 Chrome，但模型部分主要使用开发人员准备的模拟回答。真实模型接口已接入，本次未完成真实模型加浏览器的端到端验收。

你随后遇到的编号重复、测试数据引用不合规、返回结构不对，说明真实模型到内部测试格式之间的衔接仍不稳定。不能因为之前测试通过，就把这些问题归到你的输入或操作上。

## 2. 四轮分别增加了什么

| 阶段 | 实现的内容 | 对用户意味着什么 |
| --- | --- | --- |
| 第一轮 | 多步骤测试设计和审核，增加统一的数据格式 | 不再只能表达原来的 arXiv 任务，但模型必须返回合规方案 |
| 第二轮 | 根据当前页面安排操作，在同一 Chrome 会话中继续执行 | 页面跳转、填写内容和页面状态不用每一步重来；操作代码可保存核查 |
| 第三轮 | 按标准比较实际证据，有限补采与恢复 | 区分功能不符、操作失败和证据不足，不把所有异常都说成网站 Bug |
| 第四轮 | 接入界面、命令行和报告，增加目标选择及跨场景验收 | 有了统一入口，但动态模板的 JSON 操作、真实模型稳定性和错误提示仍需改进 |

## 3. 为什么同时保留 v0.3 和 v0.4

### v0.3 兼容流程：原来较固定的演示路线

它主要针对 arXiv 风格的搜索、结果列表和论文详情页。程序已经知道大致业务流程，再按关键词等参数执行，不是随便输入一个网站任务都能做。可选择本地正常仿真页、受控缺陷页，以及需要明确授权的真实 arXiv。

无需 Key 的模板演示保留了原来的有限行为，不能理解任意自然语言。写了不相关需求，也不能期待它完成新业务。

保留的原因是：原来的演示和使用方式还能继续用；新流程出问题时能与旧流程对照；升级时能检查原有能力有没有被破坏。**使用 v0.4 前不必先运行 v0.3，也不必学习两套流程。**

### v0.4 动态流程：按本次需求和当前页面安排多步测试

它先确定步骤和检查标准，再观察网页有哪些控件，生成受限制的 Selenium 操作，执行后重新观察，最后依据实际读取的结果判断。不同任务可以走不同步骤，不再只有旧版搜索路线。

“动态”不等于无限制。目前支持的是有限网页操作和证据类型，没有通用登录、支付、复杂拖拽、任意嵌入页面和跨域业务能力，也不会执行模型随意写出的 Python。

### 为什么还要另外选择模板和 LLM

| 选项 | 回答的问题 |
| --- | --- |
| v0.3 / v0.4 | 使用旧的固定流程，还是新的动态流程？ |
| 模板 / 真实 LLM | 测试方案来自预先准备的内容，还是由真实模型处理？ |
| 被测环境 | 浏览器去测试哪个网站？ |

所以，选 v0.4 不代表已经使用真实 AI。当前界面默认仍是 v0.3 加模板演示，保留无需 Key 的旧入口；这不是动态自然语言能力的默认验收入口。

## 4. 五种被测环境分别是什么

Fixture 可以直接理解为：**项目自带的练习网站、测试样板页。** 它不是模型，也不是你需要购买的软件。

选择内置 Fixture 后，程序在运行 WebAgent 的机器上临时启动网页服务，再让 Chrome 访问。该次流程结束后服务关闭，端口可能每次不同，报告里保存的地址以后不一定还能打开。

| 界面选项 | 实际是什么 | 用来检查什么 |
| --- | --- | --- |
| 本地搜索 Fixture | 小型目录检索页面，有搜索框、分类、两条样例结果与详情页 | 搜索、选分类、打开指定结果、比较列表和详情标题 |
| 本地表单 Fixture | 简化报名页面，有姓名、城市、同意条款、下一步预览与返回 | 填多字段、勾选、等待更新、核对预览及返回后的保留值 |
| 本地下载 Fixture | 提供样例 report.json 的下载页 | 下载是否完成，文件是否非空，基础格式是否有效 |
| 指定本地起始 URL | 你自己已经启动的网站 | 测试你的本机开发项目，而不是项目自带页面 |
| 外部网站（需明确授权） | 不属于本机回环地址的网站或服务 | 在你有权测试且符合限制时尝试其他网站；本轮未完成此类验收 |

### 为什么保留这些练习页面

它们让开发人员重复检查执行、证据和恢复机制，不必依赖外网站点与网络。搜索、表单、下载的结构不同，也能检查程序是不是只会一个固定流程。

但它们是简化样板。搜索页有固定样例内容，不是真实搜索引擎；表单没有真实账号、数据库报名和支付；下载页提供固定样例文件。**样例数据可以固定，测试结论必须来自实际操作和比较，不能由页面直接宣布 PASS。**

### 指定本地起始 URL 怎么用

例如你已启动自己的项目，地址为 http://127.0.0.1:8000/，把它填进来，WebAgent 就从这里开始。它不会替你启动业务项目，也不会自动修好服务。

当前本地入口只认 localhost、127.0.0.1 等回环地址。192.168.1.20 这样的局域网地址，即使也是你的服务，在程序里仍需要走外部网站授权入口。

“本机”指运行 WebAgent 和 Chrome 的机器。以后如果部署到服务器，localhost 指服务器，不是你手边的电脑。

### 外部网站不是随便输入网址就能测

需要你确认有权进行此次低频测试。勾选只是给程序许可，不替你取得网站授权，也不会绕过登录、验证码、反自动化机制或网络限制。

当前只开放起始地址的同源范围。不同子域、端口、第三方登录、支付跳转、CDN 等其他来源请求可能被拦，影响页面正常工作。仅凭这种访问失败，不能认定网站有 Bug。

## 5. Mock LLM、模板、真实 LLM 有什么区别

### Mock LLM 只用于开发测试

它是“假模型接口”：开发人员预先安排它回答什么，用来检查后面的程序。它不调用真实模型，不需要 Key，也不理解你临时输入的新需求。

例如预先安排它返回“填写姓名”，可以检查浏览器是否真填了、证据有没有记录。这证明执行链路，不证明 AI 理解了新任务。当前界面没有一个让普通用户选择的“Mock LLM 自动理解需求”选项。

报告里的“Mock LLM + 真实 Chrome”意思是模型回答模拟、浏览器操作真实，不能描述成真实 AI 完整验收。

### 为什么动态模板模式还让用户填 JSON

因为它不调用模型，也没有内置一个把任意自然语言变成动态方案的离线规划器。必须有人先写好步骤、数据和检查标准，程序才能执行；这就是 TestDesign JSON。

**你觉得这不适合普通用户，是合理的。这个入口目前适合开发调试和复现，不是完善的无 Key 用户体验。** 让用户先懂内部协议、自己写好方案，再交给程序执行，不能当成“一句话自动测试”。

项目有 examples/download_design.json 可作下载演示。当前界面不会自动加载它，需要粘贴完整内容；左侧需求必须与文件的 requirement 完全一致，文件中的 $TARGET_URL 才会替换成当次地址。随意改需求而不改方案会被拒绝。这是现状说明，不建议普通用户靠手写协议解决日常测试。

### 真实 LLM 模式不应该让你手填 JSON

设计目标是：选真实 LLM，配置服务与 Key，选目标、写自然语言，内部方案由系统和模型负责。你不应手填 TestDesign JSON。

但当前真实输出仍可能不符合协议，界面会抛出内部异常。你已遇到的三类错误就是这条路径不稳的表现。不能承诺换个说法或重试就能解决，也不应让你逐个修字段。

要变得适合普通用户，还需改进结构化输出、有限纠错重试、中文诊断，以及模板自动加载或友好编辑。**这些是待改进项，不是本文已实现的功能。**

## 6. “允许契约声明的同源文件下载”是什么意思

这句话可以改成：**允许本次测试按已审核的计划，从当前网站下载文件。**

它包含三层限制：

1. “契约声明”：方案原本就有下载任务，并明确要检查什么。不是模型看到链接，就能自行多下载一个文件。
2. “同源”：下载地址必须和起始地址使用相同协议、主机和有效端口。
3. “允许”：下载默认关闭；即使方案写了下载，也要开启许可，并且允许动作里保留 download。

例如起始地址为 http://127.0.0.1:8000/download：

| 下载地址 | 是否同源 |
| --- | --- |
| http://127.0.0.1:8000/report.json | 是 |
| http://127.0.0.1:9000/report.json | 否，端口不同 |
| http://localhost:8000/report.json | 否，主机写法不同 |
| https://127.0.0.1:8000/report.json | 否，协议不同 |
| 另一家文件存储服务的地址 | 否，即使链接出现在当前网页上 |

这个开关不会自动添加下载步骤，也不授权其他站点。它和结果页的“下载 HTML 报告”不是一回事：前者是自动化 Chrome 从被测网站取文件，后者是你保存 WebAgent 生成的报告。

下载产物保存在本次运行目录的 downloads 子目录，不应假定在日常 Chrome 的默认下载文件夹。当前可检查完成状态、非空、大小和摘要一致性，以及支持类型的基础有效性；不等于防病毒扫描，也不等于理解任意文件的业务内容。下载成功不代表整个测试自动 PASS。

## 7. 其余界面选项怎么理解

| 选项 | 实际含义与注意事项 |
| --- | --- |
| 自然语言测试要求 | 写本次操作和预期结果。默认仍是旧任务文字，不会随新目标自动改成合适需求 |
| 服务商、模型名称 | 选择真实模型服务，Key 从环境读取，不是在需求里填。当前没有专门的连通性/协议预检向导 |
| 无界面浏览器 | Chrome 在后台执行，仍是真实浏览器，不是 Mock。取消后可看窗口，但取决于运行机器环境 |
| 可视化演示停顿 | 兼容演示使用的显示辅助；当前动态执行未接成逐步暂停或人工确认 |
| 只生成脚本，不运行浏览器 | 对 v0.4 实际是只设计和审核；不观察实时页面，也不保证生成完整 Selenium 源码。旧名称对动态模式不够准确 |
| Agent5 定向补证 | 证据不足时，在许可和预算内额外读取，不是重新提交业务 |
| Agent6 局部恢复 | 方法出问题时，有限地重新观察与调整操作，不是无限重试或修改检查标准 |
| 允许执行的动作 | 本次可用哪些操作；关掉任务必需动作可能使执行被拒绝 |
| 单独允许真实站点补证/恢复 | 初始测试许可不自动包括额外补采和恢复尝试，还要分别允许 |
| 演示故障注入 | 旧版本地演示故意制造问题，展示补证或恢复，不代表发现线上故障 |

动作名称可以这样理解：

| 名称 | 意思 |
| --- | --- |
| navigate | 打开方案允许的页面 |
| fill | 填写输入框 |
| click | 点击控件 |
| select | 选择下拉选项 |
| check | 设置勾选状态 |
| submit | 提交表单 |
| observe | 读取页面或控件信息 |
| wait | 等待所支持的页面条件 |
| download | 执行方案中的下载 |

当前界面最多一次补证、一次恢复；底层还有步数、观察次数、等待与总时限，达到限制会停止。不是一直尝试直到成功。

## 8. 六个 Agent 各自做什么

它们是同一个 Python 工程里的六个角色，不是要分别购买或部署的六个模型服务，也不代表每一步都调用模型。

| 角色 | 用户可以怎样理解 |
| --- | --- |
| Agent1 | 整理需求，生成步骤和检查项，不直接操作网页 |
| Agent2 | 检查是否漏要求、改目标或缺判断标准，通过后固定方案 |
| Agent3 | 看当前网页结构，决定找哪个目标，生成受限制的操作代码 |
| Agent4 | 持有浏览器，实际操作和读取结果，保持同一会话 |
| Agent5 | 按既定标准比较实际证据，缺证时可请求补采 |
| Agent6 | 判断执行问题能否有限恢复，不能把功能失败改成通过 |

Pipeline 是统一调度程序，管理顺序、权限、预算、记录和关闭浏览器。“契约”就是审核后固定的测试计划与标准；“Oracle”就是具体检查标准，例如“详情标题等于选中结果标题”；“Evidence”就是实际读到的值或文件记录。

页面观察（DOM Observation）是网页结构的有限摘要，例如按钮、名称、文字、状态和关系，不是人眼看到的完整网页，也不等于视觉识别。当前动态结果可能没有截图，不能把“后台截图”这个界面文字理解成每步必有截图。

## 9. 怎样写需求更容易判断结果

写清起点、输入、操作对象和预期结果。例如：

> 搜索“机器人”，分类选择“机器人”，打开第二条结果，确认详情标题和第二条结果标题一致。

> 姓名填写“李四”，城市选择“北京”，勾选同意条款，进入预览后确认姓名为“李四”；返回上一步，确认姓名仍是“李四”。

> 下载报告，确认文件已完成下载且不是空文件，并检查 JSON 基础格式是否有效。

这些例子说明需求写法，不保证当前真实模型一定能生成合规方案。不要只写“测一下有没有 Bug”，因为程序需要知道什么结果才算对。也不要在需求中粘贴真实密码、Cookie 或 API Key。

## 10. 运行后怎么看结论和记录

| 状态 | 意思 | 不应该怎样理解 |
| --- | --- | --- |
| PASS | 本次必要检查项有被认可的证据且通过 | 不是整个网站没有 Bug，也不是所有业务都测过 |
| FAIL | 实际证据确认检查项不符合预期 | 不能靠修改预期或反复重试消掉 |
| ERROR | 执行、权限、环境等阻止正常验证 | 不能直接认定应用 Bug |
| INCONCLUSIVE | 必要证据不足，且无已确认失败 | 不是通过；只规划未执行也不能算 PASS |

既有确认失败又有其他缺证时，应优先报告 FAIL。直接显示“执行未完成：ValueError…”时，可能还没生成完整结果对象，不一定有完整 HTML 报告。

有结果时，可按界面标签查看需求与审核方案、步骤状态、定位依据、页面观察、实际代码、证据、补证和恢复历史，最后下载报告。产物在 artifacts 下，每次分开保存。Python 和 JSON 主要供核查排障，普通用户不应必须理解它们才能开始测试。

## 11. 你已经遇到的三个报错说明什么

| 报错 | 人话解释 | 当前应归到哪里 |
| --- | --- | --- |
| Duplicate requirement_id | 两项用了同一编号，或引用同一原文后得到重复编号，无法明确关联 | 方案、模型输出及协议处理 |
| Numeric/boolean test data must occur verbatim in source_quote | 数字或真假值在引用原文里找不到程序要求的写法 | 可能编了值，也可能文字转换后的严格校验不匹配 |
| Agent1 must return a v0.4 JSON object | 第一个角色没返回要求的对象，或缺少字符串类型的原始需求字段 | 模型输出格式与内部接口衔接 |

这些通常发生在设计阶段，不能归到网络防护或 Chrome，更不是被测网站功能失败。拒绝歧义数据有必要，但缺少清楚诊断和有限自动修订，是产品尚未完善的部分。本文未对你三次运行逐条取证，不虚构具体是哪条模型回答出了问题。

## 12. 网络、费用和数据流要注意什么

本地网站和真实 LLM 是独立选择。**测的是本地页面，也可能联网调用模型，并产生模型服务费用。** 不用真实模型的模板/模拟测试不依赖模型 API；但 Chrome 仍需浏览器与匹配驱动，缺驱动时管理程序可能联网获取。

真实模型会收到需求及用于规划/定位的页面摘要。当前有敏感字段过滤和数据量限制，但不是完整隐私识别，也不保证所有数据绝不出本机。不要拿含真实敏感资料的页面直接试验。

访问失败需区分：目标没启动、浏览器/驱动环境、模型 API 连通性、项目主动限制跨源请求，以及网站限制自动化。允许外部网站不会自动解决这些问题，也不应靠关闭安全校验求通过。
